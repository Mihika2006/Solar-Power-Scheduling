# DSSRES Solar Dashboard

AI-optimized agricultural load scheduling for solar power generated by doped
ZnO/TiO2 dye-sensitized solar cell (DSSC) electron transport layers.

A FastAPI backend trains a Random Forest model on hourly weather data, forecasts
next-day solar irradiance, converts that forecast into real power output using
lab-measured DSSC efficiency, and runs a priority-based decision tree that
schedules farm loads (irrigation, cold storage, a crop dryer) against the
predicted generation. A vanilla JS + Chart.js frontend visualizes all of it.

## How it works

**1. Weather data** (`backend/weather_service.py`)
Hourly irradiance, temperature, humidity, and cloud cover for the last 45 days
at the requested coordinates. Tries NASA POWER's live API first; if that call
fails for any reason (network, malformed payload, insufficient data), it falls
back automatically to a physically-shaped synthetic generator built from solar
geometry (clear-sky irradiance by latitude/day-of-year/hour, attenuated by a
simulated cloud layer) see **Sample / dummy data**, below.

**2. Forecasting model** (`backend/ml_engine.py`)
A `RandomForestRegressor` trained on time-of-day and time-of-year encodings
(sine/cosine), temperature, humidity, cloud cover, and a computed clear-sky
irradiance feature. Trained on all but the most recent 72 hours, evaluated on
that chronological hold-out (no shuffling, no leakage), then used to forecast
the next 24 hours.

**3. Calibration coupling**
Forecasted irradiance `G(t)` is converted to actual power using:

```
P_pred(t) = G(t) × A × eta_exp × C_temp
```

where `A` is panel area (m²), `eta_exp` is the selected material's lab-measured
efficiency (%), and `C_temp = 1 − 0.0045 × (T − 25)` is a temperature
derating factor. Efficiency values for each dopant come from
`backend/materials_data.py` (see below).

**4. Load scheduling** (`backend/scheduler.py`)
A three-level priority decision tree:
- **Level 1 Irrigation** (3.5 kW): the 4 strongest-generation hours of the day.
- **Level 2 Cold storage** (2.0 kW): runs continuously whenever power remains
  after irrigation is served.
- **Level 3 Crop dryer** (1.5 kW): only runs on leftover surplus, up to 6
  hours.

The API also returns grid energy saved, CO2 avoided, and the generation gain
of the doped material versus an undoped control.

## Sample / dummy data

**There are no static sample-data files in this repo** (no CSVs or fixture
JSON) everything is generated at request time:

- **Weather** has no fixture either, but effectively ships with its own dummy
  data generator: `generate_synthetic()` in `weather_service.py` runs
  automatically whenever live NASA POWER access fails, and also on demand if
  the frontend's "NASA POWER live" checkbox is unticked. So the app always has
  something to simulate against, with no setup required and no external API
  dependency to get a first result.
- **Material efficiency values** are hardcoded in `backend/materials_data.py`
  as the `MATERIALS` dict (Control, Ag, Cu, Mn, La), each with a `voc`, `jsc`,
  `ff`, and `eta` labeled in the module docstring as "lab-measured." They are
  the closest thing to sample/seed data in the project treat them as
  placeholders to replace with your own measured I–V results once available,
  not as data pulled from a file.

If you want an actual static sample dataset (e.g., to test offline or share a
fixed result), the straightforward way to add one is to cache one `get_weather()`
response to a CSV/JSON fixture and add a loader branch in `weather_service.py`
that reads it instead of calling `generate_synthetic()` or NASA POWER.

## Project structure

```
backend/
  main.py             FastAPI app: /api/materials, /api/iv-curve/{dopant}, /api/simulate
  materials_data.py    Lab-measured DSSC parameters per dopant + J-V curve reconstruction
  ml_engine.py          Random Forest forecaster + calibration equation
  scheduler.py          Priority-based load scheduling + savings summary
  weather_service.py    NASA POWER client with synthetic fallback
  requirements.txt
frontend/
  index.html            Dashboard layout (material metrics, I-V curve, 24h chart, savings)
  app.js                Fetches from the API and renders Chart.js charts
  styles.css
```

## Running it

```bash
cd backend
pip install -r requirements.txt
python main.py
```

This starts the API and serves the frontend together at
**http://localhost:8000**. The frontend auto-detects whether it's being
served by the API or opened directly as a file, and points its requests at
`http://localhost:8000` either way (see the `API` constant at the top of
`frontend/app.js`), so you can also open `frontend/index.html` directly in a
browser while the backend runs separately.

No API key or environment variables are required. NASA POWER's endpoint is
public; if it's unreachable from your network, the app transparently switches
to the synthetic data generator and still produces a full result.

## API reference

| Endpoint | Method | Description |
|---|---|---|
| `/api/health` | GET | Liveness check |
| `/api/materials` | GET | List all dopant materials with their lab parameters |
| `/api/iv-curve/{dopant}` | GET | Reconstructed J-V curve for one dopant vs. the undoped control |
| `/api/simulate` | POST | Full pipeline: weather → forecast → calibration → schedule |

`/api/simulate` body:

```json
{
  "dopant": "La",
  "area_m2": 120.0,
  "latitude": 22.0,
  "longitude": 78.0,
  "use_live_weather": true
}
```
